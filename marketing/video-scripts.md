# 短视频与演示脚本

优先做下面四支，每支只讲一个结果。画面必须来自真实产品操作；第一次加载 AI 模型时保留真实等待提示，不用“秒开”误导用户。

## 1. 对比：手机照片暴露了住址

时长：30–35 秒  
比例：9:16  
渠道：视频号、抖音、B站竖屏

| 时间 | 画面 | 字幕 / 口播 |
|---|---|---|
| 0–3 秒 | 一张普通自拍，镜头快速拉近到照片信息 | “这张照片可能带着你拍摄时的位置。” |
| 3–8 秒 | 在 Tubox EXIF 工具中选择照片，展示拍摄设备和 GPS 字段 | “不是相册里能看到的，是藏在 EXIF 里的信息。” |
| 8–18 秒 | 勾选删除元数据，保留方向与 ICC，导出 | “直接删除元数据段，不重新压缩画面。” |
| 18–25 秒 | 展示处理前后文件信息 | “发群、发二手平台之前，先检查一次。” |
| 25–30 秒 | 手机浏览器和 `tubox.top` CTA | “图片在浏览器本地处理，不上传。tubox.top” |

发布正文：

```text
很多人发照片前会检查背景，却忘了照片本身可能带着 GPS、设备型号和拍摄时间。

我用图盒 Tubox 的 EXIF 工具做了个检查：可以直接看到位置字段，再删除元数据。它删的是文件里的元数据段，不会为了去信息把整张图重新压一遍。

照片只在浏览器本地处理，不上传。第一次用某类工具可能需要加载资源，网络慢时耐心等一下。

工具：https://tubox.top/exif?utm_source=bilibili&utm_medium=social&utm_campaign=growth_202611&utm_content=exif_privacy
```

## 3. 对比：自拍做一张可打印证件照

时长：35–40 秒  
比例：9:16  
渠道：视频号、抖音

| 时间 | 画面 | 字幕 / 口播 |
|---|---|---|
| 0–3 秒 | 普通自拍和“去照相馆？”标题 | “临时要证件照，手机自拍也能开始。” |
| 3–9 秒 | 选择一寸 / 二寸或具体国家规格 | “先选规格，不是所有平台都能用同一种尺寸。” |
| 9–17 秒 | 模型加载、自动构图和换底 | “首次加载会慢一点，处理在本机完成。” |
| 17–27 秒 | 调整头部位置、背景色和体积限制 | “构图不满意可以手动调，报名照先检查官方要求。” |
| 27–34 秒 | 生成冲印排版并下载 | “需要打印时，可以直接排到 6 寸相纸。” |
| 34–40 秒 | 免责提示和 CTA | “最终仍要以办事机构要求为准。tubox.top” |

不要写“任何证件照都能通过审核”。正确表述：

```text
工具会按常见规格辅助构图和调整体积，但证件照是否合格仍以办理机构的最新要求为准。
```

## 4. 数据：20 张商品图压到目标体积

时长：25–30 秒

| 时间 | 画面 | 字幕 / 口播 |
|---|---|---|
| 0–3 秒 | 一个文件夹里体积超标的商品图 | “商品图一张张压，太浪费时间。” |

| 8–15 秒 | 输入目标体积，例如 200KB，开始处理 | “直接设置目标体积，不用反复猜质量。” |
| 15–22 秒 | 展示处理前后体积和 ZIP | “处理完成后一次打包。” |
| 22–27 秒 | 设备本地处理提示 | “图片不需要上传，浏览器里处理。” |

英文字幕版：

```text
Batch resize 20 product images.
Set a target file size.
Download everything as one ZIP.

Processed locally in your browser.
tubox.top/en/batch
```

## 拍摄检查

- 录屏前隐藏个人信息、真实文件名和客户资料。
- 使用同一台设备、同一张样本图，前后对比才有可信度。
- 首次加载模型、失败回退和重新尝试可以剪掉等待，但不能拼接成“瞬间完成”。
- 竖屏内容前 3 秒必须出现结果或冲突，不要用品牌 Logo 当第一帧。
- 每条只使用一个 UTM 链接，评论置顶放同一入口。
